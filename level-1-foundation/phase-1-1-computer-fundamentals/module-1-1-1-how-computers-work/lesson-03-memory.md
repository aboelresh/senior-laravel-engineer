# الدرس الثالث: الذاكرة — كيف تعمل من الداخل؟

## مصطلحات مهم تعرفها قبل ما نبدأ

| المصطلح | المعنى |
|---------|--------|
| DRAM — Dynamic RAM | النوع الشائع من الـ RAM يعتمد على Capacitors |
| Capacitor | مكثف كهربائي يخزن شحنة تمثل 0 أو 1 |
| Transistor | مفتاح كهربائي يتحكم في الوصول للـ Capacitor |
| DRAM Refresh | إعادة شحن خلايا الـ RAM آلاف المرات في الثانية |
| ROM — Read-Only Memory | ذاكرة ثابتة تحتوي برامج لا تتغير كالـ BIOS |
| BIOS / UEFI | برنامج يعمل فور تشغيل الجهاز قبل نظام التشغيل |
| Flash Memory | نوع متطور من ROM قابل للمسح وإعادة الكتابة |
| HDD — Hard Disk Drive | قرص صلب ميكانيكي يعمل بأقراص دوارة |
| SSD — Solid State Drive | قرص صلب إلكتروني بدون أجزاء متحركة |
| NAND Flash | تقنية التخزين المستخدمة في الـ SSD |
| Cache Hit | إيجاد البيانات المطلوبة في الـ Cache مباشرة |
| Cache Miss | عدم إيجاد البيانات في الـ Cache والاضطرار للـ RAM |
| Temporal Locality | البيانات المستخدمة مؤخراً ستُستخدم مجدداً قريباً |
| Spatial Locality | البيانات المجاورة لما استُخدم ستُستخدم قريباً |
| Virtual Memory | وهم تصنعه الـ OS يجعل كل Process تعتقد أنها تملك الذاكرة كلها |
| Page Table | جدول يترجم العناوين الوهمية إلى عناوين RAM حقيقية |
| Swapping | نقل صفحات الذاكرة غير المستخدمة إلى الـ Storage مؤقتاً |
| Memory Pressure | حالة يكون فيها الطلب على الـ RAM أكبر من سعتها |
| OOM Killer | آلية في Linux تُغلق Processes قسراً عند نفاد الذاكرة |

## شرح المفاهيم

### أولاً: لماذا نحتاج ذاكرة أصلاً؟

المعالج يملك عدداً محدوداً من الـ Registers لا تتجاوز سعتها الإجمالية 128 byte في المعالجات الحديثة. متصفح واحد قد يحتاج أكثر من 500 MB. هذا التفاوت الهائل هو السبب الجوهري لوجود الذاكرة الخارجية.

### ثانياً: DRAM — كيف تخزن الـ RAM البيانات؟

كل خلية في الـ RAM تتكون من:

```
Transistor (مفتاح كهربائي)
     +
Capacitor (مكثف كهربائي)

شحنة موجودة في الـ Capacitor = 1
لا شحنة                       = 0
```

الـ Capacitor يفقد شحنته تدريجياً حتى مع وجود الكهرباء، لذلك يقوم Memory Controller بإعادة شحن كل خلية آلاف المرات في الثانية في عملية تُسمى DRAM Refresh. عند انقطاع الكهرباء تتبدد الشحنات فوراً وتختفي البيانات. هذا ليس عيباً بل تصميم مقصود، إذ إن الـ Capacitor الذي يفقد شحنته بسرعة هو نفسه الذي يُشحن ويُفرغ بسرعة هائلة تحقق السرعة المطلوبة.

### ثالثاً: ROM و Flash Memory

الـ ROM ذاكرة ثابتة لا تُمسح بانقطاع الكهرباء، صغيرة الحجم، تحتوي برامج لا تتغير كالـ BIOS الذي يعمل فور تشغيل الجهاز ليفحص الـ Hardware ويُحمّل نظام التشغيل.

الـ Flash Memory نوع متطور من ROM يمكن مسحه وإعادة برمجته. تُستخدم في الـ SSD وبطاقات SD ومحركات USB. كل خلية NAND Flash تحبس الإلكترونات في Floating Gate محاط بعازل، وهذه الإلكترونات لا تحتاج طاقة مستمرة للبقاء مما يجعل البيانات دائمة. لكن لكل خلية عدد محدود من دورات الكتابة مما يجعل للـ SSD عمراً محدوداً.

### رابعاً: HDD مقابل SSD

```
HDD:
أقراص دوارة بسرعة 7200 RPM
رأس قراءة يتحرك ميكانيكياً فوق القرص
وقت الوصول: 5-10 ms
السبب: Seek Time + Rotational Latency

SSD:
خلايا NAND Flash إلكترونية بدون أجزاء متحركة
وقت الوصول: 0.1 ms
أسرع بـ 50-100 مرة من HDD في الوصول العشوائي
```

| المعيار | HDD | SSD |
|---------|-----|-----|
| السرعة | 100-200 MB/s | 500-7000 MB/s |
| وقت الوصول | 5-10 ms | 0.1 ms |
| الأجزاء | متحركة ميكانيكية | لا أجزاء متحركة |
| العمر | 3-5 سنوات | 5-10 سنوات |
| السعر | رخيص | أغلى |

### خامساً: هرم الذاكرة

```
Registers     ← 0.3 ns  / bytes    / داخل المعالج
L1 Cache      ← 1 ns    / KB       / داخل Core
L2 Cache      ← 5 ns    / MB       / داخل Core
L3 Cache      ← 20 ns   / MB       / مشترك بين Cores
RAM           ← 100 ns  / GB       / على اللوحة الأم
SSD           ← 100 µs  / مئات GB  / منفصل
HDD           ← 10 ms   / TB       / منفصل
```

### سادساً: Cache Hit و Cache Miss

```
Cache Hit Rate في تطبيقات جيدة: 95%+

Cache Hit:
المعالج يطلب بيانات → موجودة في Cache
الوقت: 1-5 ns 

Cache Miss:
المعالج يطلب بيانات → غير موجودة في Cache
الوقت: 100+ ns 
```

يعتمد الـ Cache على مبدأين:

**Temporal Locality:** البيانات المستخدمة مؤخراً ستُستخدم مجدداً. مثال: متغير داخل حلقة تكرار يبقى في الـ Cache طوال تنفيذ الحلقة.

**Spatial Locality:** البيانات المجاورة لما استُخدم ستُستخدم قريباً. عند طلب بيانات من عنوان معين يجلب الـ Cache Cache Line كاملة من العناوين المجاورة.

### سابعاً: Virtual Memory و Swapping

كل Process تعتقد أنها تملك الذاكرة كلها لنفسها. هذا وهم مقصود يصنعه نظام التشغيل باستخدام Page Table تترجم العناوين الوهمية إلى عناوين RAM حقيقية.

عند امتلاء الـ RAM:

```
الصفحات الأقل استخداماً تُنقل إلى Swap على SSD
عند الحاجة إليها تعود إلى RAM
صفحة أخرى تذهب إلى Swap

الأثر على الأداء:
RAM:  0.1 ms
SSD:  100 ms
أبطأ بـ 1000 مرة
```

هذه الحالة تُسمى Memory Pressure وهي سبب شائع لبطء السيرفرات. إذا امتلأ Swap أيضاً يتدخل OOM Killer لإغلاق Processes قسراً.

## الأسئلة والإجابات

**السؤال الأول:** لماذا الـ RAM مؤقتة وليس هذا عيباً؟

لأن الـ DRAM تخزن البيانات كشحنات كهربائية في Capacitors تحتاج طاقة مستمرة للبقاء. عند انقطاع الكهرباء تتبدد الشحنات وتختفي البيانات. هذا تصميم مقصود لتحقيق سرعة عالية جداً، إذ إن الـ Capacitor الذي يفقد شحنته بسرعة هو نفسه الذي يُشحن ويُفرغ بسرعة هائلة. السرعة والدوام في تعارض واختار المهندسون السرعة للـ RAM والدوام للـ Storage.

---

**السؤال الثاني:** ما الفرق بين ROM و Storage؟

ROM ذاكرة ثابتة صغيرة الحجم تحتوي برامج لا تتغير كالـ BIOS، ولا تُستخدم لحفظ ملفات المستخدم. أما Storage فذاكرة دائمة كبيرة الحجم يُستخدم لحفظ نظام التشغيل والبرامج والملفات وكل بيانات المستخدم. الـ Flash Memory كالـ SSD هي تقنياً نوع متطور من ROM قابل للكتابة لكنه يختلف جوهرياً عن ROM الكلاسيكية من حيث الحجم والغرض.

---

**السؤال الثالث:** سيرفر RAM = 4 GB والتطبيق يحتاج 6 GB. ماذا يحدث؟

تمتلئ الـ RAM فيبدأ نظام التشغيل باستخدام Swap على الـ SSD. الصفحات الأقل استخداماً تُنقل إلى Swap وتعود عند الحاجة. بما أن SSD أبطأ بألف مرة من RAM يحدث تباطؤ حاد. إذا امتلأ Swap أيضاً يتدخل OOM Killer لإغلاق Processes قسراً وقد يتوقف التطبيق.

---

**السؤال الرابع:** ما هو Cache Hit Rate ولماذا يهم مهندس الـ Backend؟

Cache Hit Rate النسبة المئوية للمرات التي يجد فيها المعالج البيانات في الـ Cache دون الرجوع للـ RAM. في Backend نحاكي هذا المبدأ بـ Redis: بيانات في Redis تُقرأ في 1 ms بينما نفس البيانات من Database تحتاج 100 ms. رفع Cache Hit Rate يعني استجابة أسرع وقدرة على خدمة عدد أكبر من المستخدمين بنفس الموارد.

---

**السؤال الخامس:** متى تكون زيادة RAM قراراً صحيحاً ومتى تكون هدراً؟

زيادة RAM صحيحة عندما تكون الـ RAM ممتلئة باستمرار ويُستخدم الـ Swap بكثرة وتُثبت القياسات أن Memory Pressure هي السبب الفعلي للبطء. أما إذا كان استهلاك RAM طبيعياً فالمشكلة في مكان آخر كـ SQL بطيئة أو Disk I/O أو الكود نفسه، وزيادة RAM لن تحل شيئاً. القاعدة: قِس أولاً ثم قرر.

---

**السؤال السادس:** ما هو Cache Coherence Problem في المعالجات متعددة الأنوية؟

عندما يحتفظ أكثر من Core بنسخة من نفس البيانات في Cache الخاص به، وعدّل أحد الـ Cores تلك البيانات، تصبح نسخ الأنوية الأخرى قديمة وغير متطابقة. الحل هو بروتوكول MESI الذي يُرسل Invalidate Signal لكل الأنوية عند تعديل بيانات مشتركة. في PHP التقليدي لا توجد هذه المشكلة لأن كل Request Process منفصلة لا تشارك ذاكرتها، لكنها تظهر عند استخدام Laravel Octane مع Workers مشتركة.

---

**السؤال السابع:** كيف يحل Laravel Octane مشكلة إعادة تحميل Framework في كل Request؟

بدلاً من إنشاء Process جديدة لكل Request يُشغّل Octane Workers طويلة العمر تبقى في الذاكرة. Laravel يُحمَّل مرة واحدة فقط وكل الـ Requests تستخدم نفس النسخة الموجودة في RAM. هذا يقلل استهلاك CPU والـ RAM ويرفع عدد الـ Requests التي يستطيع السيرفر معالجتها. لكنه يستلزم الانتباه لمشكلة State Pollution إذ إن البيانات المخزنة في Static Variables تبقى بين الـ Requests.

## ملاحظات الأداء

- تفعيل OPcache يقلل القراءة من Disk ويُبقي الـ Opcodes في RAM مما يُقلل Disk I/O بشكل ملحوظ.
- في Production يجب مراقبة استهلاك RAM و Swap باستمرار باستخدام أدوات مثل `free -h` و `vmstat`.
- زيادة RAM لا تحل مشاكل بطء الـ Database أو سوء الكود.
- استخدام Lazy Loading و Cursor في Laravel يقلل الذاكرة المستهلكة عند معالجة بيانات ضخمة.

## ملخص

الذاكرة منظومة متكاملة تتدرج من الـ Registers السريعة جداً داخل المعالج حتى الـ HDD البطيء. الـ RAM سريعة ومؤقتة بتصميم مقصود. الـ ROM ثابتة للبرامج الحيوية. الـ SSD سريع ودائم للتخزين. الـ Cache تحل مشكلة الفجوة بين سرعة المعالج وسرعة الـ RAM. Virtual Memory تتيح تشغيل برامج تتجاوز حجم الـ RAM المتاحة. فهم هذه المنظومة يمكّن مهندس الـ Backend من تشخيص مشاكل الأداء المتعلقة بالذاكرة واتخاذ قرارات صحيحة في ضبط السيرفر والتطبيق.
